# External IP intake — architecture recommendation, not integration acceptance

2026-09-05 · rtl-engineer · local only. No project RTL, DV, flow, or spec changed.

## Decision inputs

Recommend **native PicoRV32 RV32IM plus a project-owned error-aware native→AXI bridge** for B1 control. Official `picorv32_axi` is a real 32-bit AXI4-Lite master, but has **no RRESP/BRESP input at all**. Its adapter returns `mem_ready = mem_axi_bvalid || mem_axi_rvalid`, so it cannot preserve the system error contract. Source: [pinned complete upstream source](sources/picorv32/picorv32.v), lines 2543–2570 and 2731–2788. This corrects an integration assumption, not the upstream source. The new bridge does not exist in this intake.

Use **32-bit system AXI4, 32-bit CSR AXI-Lite and 32-bit NPU DMA** in the first contract. There is no width conversion on this path. A bounded project crossbar is a feasible build item with a small contract, but is not an acquired or validated IP. Pinned MIT `verilog-axi` supplies an actual synthesizable fallback (`axi_crossbar`, `axi_axil_adapter`), at the cost of strict-lint failures and upstream deprecation. Do not call its AXI→AXI-Lite converter an AXI-Lite→AXI bridge.

For S1 research select **Caliptra Core v2.1.2 in passive mode**, with ROM `rom-2.1.2` and firmware `fw-2.1.2` as compatible, pinned candidates. The application/host boot controller must supply fuse values/entropy/firmware, authorize its application image, enforce isolation, and release the application CPU. Passive core does not autonomously own SoC boot. The full subsystem is a separate, substantially larger option, not a mailbox peripheral drop-in.

## CPU integration contract facts

- Source commit: `a473fc8fca393771d83b0ffcf0b14db3393339d8`, ISC license retained. All CPU RTL is in the one complete upstream `picorv32.v`; no upstream test sources acquired or opened.
- Probe config: `ENABLE_MUL=1`, `ENABLE_DIV=1`, `ENABLE_IRQ=1`, `ENABLE_IRQ_QREGS=1`, `COMPRESSED_ISA=0`, `PROGADDR_RESET=0`, `PROGADDR_IRQ=0x100`, `STACKADDR=0x10040000`. Other settings remain upstream defaults, including dual-port registers, counters, misalignment/illegal catches, latched IRQs, IRQ timer, iterative multiply, no barrel shifter, no external PCPI.
- `picorv32` native bus: `mem_valid`, `mem_instr`, `mem_ready`, `mem_addr[31:0]`, `mem_wdata[31:0]`, `mem_wstrb[3:0]`, `mem_rdata[31:0]`. Unified instruction/data port, valid/ready, one transaction at a time; request remains stable until ready. Lookahead outputs are optional and must not be mistaken for a second transaction port.
- Clock `clk`; synchronous active-low `resetn`. External IP does not satisfy the repository's blanket all-flops-reset rule: upstream intentionally leaves general registers uninitialized (except optional SP), and uses ordinary Verilog `always`. Architect/integrator must explicitly address imported-IP conventions; do not silently claim native conformance.
- Official AXI wrapper: AW/AR address 32 and PROT 3, WDATA/RDATA 32, WSTRB 4, separate AW/W/B/AR/R handshakes; no ID, burst, SIZE, LAST, USER, RRESP or BRESP ports. `AWPROT=0`, `ARPROT=mem_instr?4:0`. This port is not the old Wishbone wrapper.
- No data/instruction cache array or cache-coherence interface. There is instruction prefetch; “uncached” does not permit instruction-memory rewrites without a defined restart protocol.
- Standard FENCE opcode `0001111`, funct3 `000` is recognized (source line 1088); `FENCE.I` funct3 `001` is not. Accepted FENCE does not flush external fabric/DMA writes. Enforce DMA completion after all write B responses and memory visibility, then publish done/IRQ; software barriers also need compiler memory clobbers. For boot, finish executable SRAM load before execution and forbid self-modifying code in B1.
- IRQ handling is explicitly **not RISC-V privileged ISA**: `irq[31:0]`, `eoi[31:0]`, `getq/setq/maskirq/retirq/waitirq/timer`. No standard `mtvec/mepc/mcause/mstatus` exception contract is established. IRQ 0 timer; 1 EBREAK/ECALL/illegal; 2 misaligned access. Reserve these and use bit 3+ for NPU. `q0` is return address; `q1` contains pending serviced mask; `q2/q3` are uninitialized scratch. EOI asserts on handler entry, deasserts on return; it is not a substitute for peripheral status acknowledgement. All interrupts start masked and firmware must unmask the selected sources. Fatal/illegal paths while already in handler or masked can trap rather than nest.
- Native core also has **no memory-error input**. Error-aware bridge must latch fault metadata, withhold successful `mem_ready` on failed load/fetch, stop further execution via system-defined reset/fatal control, and have separately observable recovery. Raising IRQ alone while indefinitely withholding ready does not guarantee servicing the IRQ. Do not advertise a precise standard load-access exception. Fault-response behavior remains a new RTL/DV work item.
- RV32IM has no F/D floating point. Compiler target `-march=rv32im -mabi=ilp32` plus soft-float libraries is a reasonable SW choice, not tested here. Upstream publishes iterative MUL=40, MULH=72, DIV/REM=40 cycles under its stated assumptions; these are not LLM measurements. `expf/sqrtf`, normalization, softmax, activation and FP conversion can dominate execution. SW owner must measure actual linked code size, scratch/stack and simulated cycle/wallclock cost. Good control CPU recommendation does not prove L1 latency or product throughput.

## AXI fabric and width paths

Pinned `alexforencich/verilog-axi` commit `516bd5dadc3365b7f9e225d2af8fe0b8d804fe53`, MIT. README explicitly says deprecated and superseded by `fpganinja/taxi`; this intake neither imports taxi nor assumes its license/tool compatibility. Selected RTL dependency closure only; no tests acquired.

- `axi_crossbar` is full AXI4 with separate read/write arbitration, ID ordering, decode/error logic. Source defaults are DATA/ADDR=32, S_COUNT=M_COUNT=4, S_ID_WIDTH=8, M_ID_WIDTH=S_ID_WIDTH+$clog2(S_COUNT). Default-config probe does **not** validate the proposed 2-bit-ID contract or actual address map. Two initiators with per-input 2-bit IDs would normally make this crossbar's output IDs 3 bits. An architect wanting 2-bit system IDs must allocate/remap IDs or select a custom arbiter, not truncate response IDs.
- New native→AXI bridge uses one outstanding transaction; extend single beats with LEN=0, SIZE=2 for aligned 32-bit transfer, WLAST=1, LOCK=0, fixed source ID, and preserved byte strobes. Byte/halfword access and lane semantics must be frozen by architect; address alignment cannot be guessed in RTL.
- Direct first path: CPU native32→new error-aware AXI32 bridge→AXI32 fabric→ROM/SRAM/DRAM target32. NPU DMA is separate AXI32 initiator with architect-specified one read and one write outstanding. CSR path: fabric AXI32→`axi_axil_adapter` 32→32→AXI-Lite CSR32, or new restricted converter. Adapter handles full AXI→Lite and INCR/narrow transfers; CSR side effects require a narrower permitted transaction contract.
- `axil_adapter` supports AXI-Lite width adaptation. 32→64 could be used on a future Lite branch; it is not full AXI fabric. A future wide system/DMA needs a full AXI width adapter (`axi_adapter`, **not acquired or probed here**), or design-specific lane logic and independent validation. No claim that 32-bit CPU can saturate a wide NPU data bus.
- Fabric acceptance still requires independent DV: AW/W independence, backpressure, ordering, ID ownership, decode/error/timeout, reset/drain, byte-lane behavior and arbitration. No simulation occurred in this role.

## Caliptra exact integration findings

Core RTL `v2.1.2`=`49370266d12cb0c4a8f71b3a0ff7e54ba7d4866e`; Apache-2.0. Submodule Adams Bridge pin `b77e3d899e828d626cfc2a0d26a6b5704cc121e0` recorded, not cloned. Core docs, actual top and selected type/config files acquired.

- Actual top `src/integration/rtl/caliptra_top.sv` has `axi_if.w_sub s_axi_w_if`, `axi_if.r_sub s_axi_r_if` for mailbox/SoC registers; separately `axi_if.w_mgr m_axi_w_if`, `axi_if.r_mgr m_axi_r_if` for DMA assist. **External host is AXI, not AHB.** VeeR's internal AHB does not impose an external AHB bridge. An AHB-only host would need its own adapter; this 32-bit AXI system does not.
- Host target config: data=32, USER=32, ID=8; SoC register window local address width=19 (512 KiB). Address decoder must range-check the complete system address before mapping low 19 bits; do not alias unrelated high addresses. System ID 2→target 8 can zero-extend if responses and outstanding contract are preserved. Source identities are security-relevant AxUSER values, **not a single trusted bit**, and cannot be software-spoofable.
- AXI target services one read/write at a time (half duplex), in order. Only mailbox data-in/data-out may burst, and only FIXED; use single full-word accesses initially. For mailbox data and TRNG: SIZE=2, WSTRB=0xF. LOCK=0. PROT/CACHE/QOS/REGION are unused. Invalid requester/address transactions return SLVERR; a CPU bridge that discards response errors is incompatible with meaningful rejection reporting.
- **Passive mode:** DMA assist is unavailable; official integration spec requires AXI manager interface inputs tied to 0 and no connection to SoC fabric. **Subsystem mode:** DMA manager default address=48 (overrideable), data=32, ID=5, USER=32. A 32-bit-address/2-bit-ID system therefore needs explicit address-range checks and ID adaptation/serialization before connecting active DMA. Do not narrow by truncation.
- Memory exports include ROM (`imem_cs/addr/rdata`), mailbox SRAM with ECC, VeeR ICCM/DCCM and Adams Bridge SRAM interfaces. Source sets ROM=98,304 bytes (96 KiB), ROM data=64; hardware spec lists ICCM=256 KiB and DCCM=256 KiB; mailbox source is 256 KiB passive or 16 KiB subsystem, plus ECC and crypto memories. These are requested memories, not achieved FPGA utilization. Hardware doc's ROM table shows an inconsistent end address `0xBFFF` despite 96 KiB; config defines range ending `0x17FFF`. Record discrepancy for upstream/spec review rather than copying the incorrect range.
- Clock `clk`, JTAG `jtag_tck`, active-high powergood and active-low warm reset; core docs require asynchronous assertion and clock-synchronous deassertion. Core uses clock gating, separate reset domains and technology-dependent SRAM/ICG integration. Official 400 MHz convergence statement is not a local timing result or FPGA promise. Reset convention differs from the project synchronous-reset rule and needs an explicit domain boundary.
- Integrator provides immutable ROM, compatible FMC/runtime image, OTP/fuse provisioning and lock sequence, obfuscation/identity material, lifecycle/debug/scan straps, clocks/resets/memory wrappers and entropy. In passive mode host waits for `ready_for_fuses`, programs required fuse/config values and fuse-done, loads firmware via mailbox, then waits for runtime readiness. Fuse-done is required after warm reset too. External TRNG mode: service `etrng_req` with entropy via architectural registers. Internal mode still requires physical noise inputs `itrng_data[3:0]/itrng_valid`. Deterministic simulation entropy is only a functional model.
- Compatible candidates: ROM `rom-2.1.2`=`45de392fb186756bb5c0770e38a5709e3fdc7acb`, firmware `fw-2.1.2`=`557fd1a9864831a7d1cdfaffd3b33fd2e26f5e93`. Tags/commits recorded, binaries not downloaded or executed; their hashes, build/signing inputs and actual boot remain S1 prerequisites. GitHub releases/latest on caliptra-sw currently resolves an older-major runtime tag, so it is not a safe compatibility selector.
- Caliptra authenticates its firmware; using services for application-image authorization still requires an explicit host protocol and policy. Host boot authority must verify authorized image bytes, enforce immutability/TOCTOU protection, apply CPU/DMA access controls, hold application reset on failure and own bounded recovery. `ready_for_runtime` or mailbox success alone does not establish application authorization or isolate DMA. Separate privileged boot controller is needed if application CPU must remain held throughout host provisioning; do not create a boot dependency cycle.
- Full subsystem alternative `css-v2.1.2+1.val.doc`=`01b0a3528e196f4219d20dd9cbfec3727869d5d9` pins the same core, adds MCU/VeeR, MCI sequencing, fuse/lifecycle control, I3C/recovery and its own MCU ROM/firmware/SRAM/reset interfaces. Top and integration docs retained; submodule trees not downloaded. It needs its own address/USER/boot/recovery contract and resource estimate. No full-core or subsystem lint/elaboration/sim/security test ran.
- Tool evidence is deliberately bounded: Caliptra AXI package/interface strict Verilator lint returns 1 with 40 unused/undriven warnings at interface-only scope. Native Yosys `read_verilog -sv` parses package then fails `axi_if.sv:21` at `import` (`unexpected TOK_IMPORT`). This supports the need to evaluate slang/sv2v or another supported frontend and flattening wrappers under an ADR; it does not prove all such paths fail or pass. Full Caliptra filelists also require Adams Bridge, generated packages, VeeR and memory/technology wrappers. Upstream documents Verilator flows separately from proprietary VIP lanes; do not require commercial VIP merely to claim Verilator exists, or claim full upstream regressions have been run.
