# AXI interface control document — §1 protocol and ports

Version 1.0-rc3. Protocol basis: Arm IHI 0022H AXI4/AXI4-Lite; selected v1 restrictions below are architectural choices, not claims that AXI universally mandates them. [Arm official specification](https://developer.arm.com/-/media/Arm%20Developer%20Community/PDF/IHI0022H_amba_axi_protocol_spec.pdf?hash=6325311012DDADF238C35A6C0FD734E520754F82&la=en&revision=71bd7c57-2ed7-487b-bc3e-68c4ab56fa5f).

**AXI-01:** All full-AXI interfaces shall carry the following signals. Initiator drives AWVALID, AWADDR[31:0], AWID[1:0], AWLEN[7:0], AWSIZE[2:0], AWBURST[1:0], AWLOCK, AWCACHE[3:0], AWPROT[2:0], AWQOS[3:0], WVALID, WDATA[31:0], WSTRB[3:0], WLAST, BREADY, ARVALID, ARADDR[31:0], ARID[1:0], ARLEN[7:0], ARSIZE[2:0], ARBURST[1:0], ARLOCK, ARCACHE[3:0], ARPROT[2:0], ARQOS[3:0], RREADY. Target drives AWREADY, WREADY, BVALID, BRESP[1:0], BID[1:0], ARREADY, RVALID, RDATA[31:0], RRESP[1:0], RID[1:0], RLAST. USER and REGION are absent (zero-width, not trusted signals). Both share clk/rst_n. No ACE, atomics, exclusives or coherent caches.

**AXI-02:** CPU source ID shall be 0 and NPU source ID 1 at both ingress and target ports. IDs 2/3 are reserved; no dynamically programmable identity. Supported transactions are aligned 32-bit beats (SIZE=2) with INCR (BURST=1), LEN=0..15, no 4-KiB boundary crossing, no region crossing, LOCK=0, CACHE=0, QOS=0. NPU AWPROT/ARPROT=0; CPU AWPROT=0 and ARPROT[2]=native mem_instr, ARPROT[1:0]=0 (values0or4 only). CPU bridge emits LEN=0 only. The native CPU already aligns addresses, replicates subword store data and supplies mapped WSTRB. Bridge passes these unchanged; on successful reads it returns the complete unshifted32-bit RDATA. Lane selection and sign/zero extension occur inside the CPU. Original read byte offset/load size are not available to the bridge. NPU emits full-word accesses and all strobes one. All target responses echo accepted ID. No reordering or interleaving within a burst.

**AXI-03:** Initiators shall hold VALID and payload stable until corresponding READY; neither address nor data VALID waits for READY. AW and W handshakes are independent. Both DUT initiators (CPU bridge and NPU DMA) shall offer AWVALID no later than the first WVALID of the same transaction, and shall assert AWVALID without waiting for AWREADY; WVALID need not wait for AWREADY. The receiver must still tolerate W handshaking before AW using a one-beat holding register or backpressure without deadlock, and must not infer an address from W. Thus a fatal/error stop always finds an offered AW for every offered DUT W; all such AW/W transactions remain in the retained drain set. Exactly LEN+1 W beats and correct WLAST are required. BVALID follows accepted AW and final W, never earlier. Read target returns exactly LEN+1 beats with RLAST only on final beat. R/B remain stable under response backpressure. Protocol violations such as incorrect WLAST are illegal initiator behavior, not software requests; protocol monitor latches fatal and requires coordinated reset rather than inventing a legal response to an ill-formed transfer.

# §2 Ordering, routing, permissions and progress

**AXI-04:** CPU bridge shall permit only one native request total until AXI response completes. NPU shall allow at most one read burst and one write burst outstanding, with fixed ID1; controller may overlap them only to disjoint buffers. Fabric shall accept at most one read and one write transaction total across all initiators, independent channels, each assigned to its selected source/target through completion. Read arbitration and write-address arbitration are separate round-robin at transaction boundaries; completed grant advances priority. Write data follows the accepted/retained AW owner; data from another source cannot mix. Arbitration considers VALID fairly; a continuously requesting source receives a grant after at most one other completed transaction. This bound assumes selected target and response consumer progress; watchdog covers stalled endpoints.

**AXI-05:** Fabric shall validate region permissions and supported address attributes before forwarding any request. CPU reads with ARPROT[2]=1 are instruction fetches and require X permission; data reads require R. Source identity remains physical port identity, independently of PROT. Only CPU ARPROT0/4 is legal; NPU PROT4 is rejected. Rejected well-formed reads return zero data, DECERR for mapping/permission or SLVERR for unsupported attributes, for exactly LEN+1 beats. Rejected writes drain exactly LEN+1 W beats then return one error B and make no target changes. AW decode alone never reports B before W drains. Burst format errors arising after partial forwarding are fatal protocol violations. Normal target SLVERR may leave already written bytes changed; failed NPU output is entirely invalid. No EXOKAY is generated.

**AXI-06:** ROM/SRAM shall respond within 16 cycles of an accepted read or the later of accepted AW/final W, absent consumer backpressure. CSR bridge shall respond within 32 cycles under the same condition. External functional-memory model shall have configurable initial latency 1..1024 cycles and per-beat backpressure 0..1024 cycles, with deterministic seed and error injection logged. The baseline is latency4, no injected stalls or errors. These are simulation target obligations; no DDR controller or PHY is validated by this model.

**AXI-07:** A progress monitor shall track each source/channel and each live transaction obligation independently. Counters are initialized to0 on the edge creating an obligation; each subsequent rising edge with no matching progress increments that obligation's counter. A matching handshake on the threshold edge wins and clears/restarts its counter; otherwise reaching65536 latches fatal(reason3). Unrelated source/channel handshakes never reset a counter. Separate obligations are: (a) every offered VALID waiting for its corresponding READY; (b) each accepted AR waiting for first/next R beat, restarted only by that transaction's R handshake until RLAST; (c) each accepted AW waiting for first/next W beat, restarted only by that transaction's W handshake until expected WLAST; (d) final W accepted waiting for matching B, beginning only once AW is accepted; (e) early accepted W waiting for its AW, begun on the first early W handshake and cleared only by that AW. Completion of a handshake already counted before obligation creation is accounted for, not awaited twice. A manager that omits required WVALID after AW cannot avoid timeout. On timeout, new transactions are blocked, CPU held in local reset, o_fatal asserted; live AXI state is retained until coordinated reset. It is forbidden to inject synthetic R/B then reuse the fabric with possible stale responses. No transaction-level cancellation exists. An early-W-with-no-AW timeout is still monitored as an illegal/incomplete input sequence even though compliant DUT initiators always offer AW first or concurrently. Its fault_addr is0 if no corresponding address was ever offered; otherwise retain the known aligned address as SYS-12 defines.

**AXI-08:** Every memory target shall commit enabled write bytes before presenting successful BVALID. A read accepted after that B handshake shall observe those bytes unless subsequently overwritten. NPU DONE/IRQ shall occur only after all successful output B handshakes; consequently CPU polling DONE then loading output sees completed data. CPU software uses compiler memory barriers around driver calls; serialized uncached CPU bridge gives the hardware order. FENCE opcode behavior is CPU-specific (dependencies.md); FENCE.I is not used, since code is loaded before the initial jump and no instruction cache/self-modifying code exists. No completion rule relies on an unsupported fence.

# §3 AXI4-Lite conversion

**AXI-09:** The single peripheral bridge shall expose Lite AWADDR32/AWPROT3/AWVALID/AWREADY, WDATA32/WSTRB4/WVALID/WREADY, BRESP2/BVALID/BREADY, ARADDR32/ARPROT3/ARVALID/ARREADY, RDATA32/RRESP2/RVALID/RREADY (no ID/LEN/SIZE/BURST/LAST). It accepts only full-word single-beat CPU transactions after firewall validation and rejects bursts without issuing Lite requests. It buffers AW and W independently, retains full-AXI ID until B, and relays response errors. One read and one write may be live; an individual CSR target may serialize by backpressure. At most one write side effect per complete AW/W pair; a stalled B response must not repeat the write. NPU CSR, system, IRQ and UART use independent Lite target ports selected by address.

# §4 External-memory boundary and observability

**AXI-10:** SIM-L1 external memory shall be an AXI functional target with 16 MiB backing, reset/preload only through declared ROM/image/input artifacts; all execution-time changes must originate from accepted DUT writes. Host/DV may read snapshots and compare independent results, but shall not update DUT logits, tokens, KV, NPU inputs, command status or completions during execution. Fault-injection policy may corrupt a designated input byte before reset release or return a bus error on a recorded transaction. Each run records accepted AR/AW/W/R/B events, ID/address/size/response and reset epoch sufficient to prove source→calculation→writeback causality.
