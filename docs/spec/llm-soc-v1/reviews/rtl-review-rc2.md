## Remaining blockers

### RC2-01 — dot unit cannot determine final-command `last` from its inputs

Locations: `npu.md:52`; `contract.json:366`–374 (`group_result.last`), `contract.json:387`–398 (`dot_operands`); C15 local→dot and C16 dot→DMA.

The prose requires dot→DMA `last` to mean “last group of final row.” Dot's only functional input is `dot_operands`, with row, group_index, group_first and group_last. It receives neither N/K/G nor a command-final marker. Local now has the descriptor, which fixes its own group formation, but that final-command information still does not reach dot.

Concrete indistinguishable input: K=4,G=4 with N=1 versus N=2 and identical first-row operands. The first operand has row0, group_index0, group_first1, group_last1 in both commands. Its result must have last1 for N=1 and last0 for N=2. The input protocol cannot distinguish them. Waiting for another operand cannot resolve the N=1 terminal case without an unspecified timeout/end signal.

Minimal correction: add `command_last` (or equivalently named final-result marker) to local→dot operands, generated by local from its descriptor and asserted only with group_last on the final row/group, then forward it with the resulting result. Alternatively remove `last` from dot→DMA and explicitly let descriptor-owning DMA derive completion from row/group_index. Choose one and synchronize machine/prose. No datapath rewrite or new test is requested. Owner: architect/NPU partition.

### RC2-02 — CPU sticky fault wrapper has only local reset, not common reset

Locations: `system.md:93`; `contract.json:416`–435 (`fault_event` and `cpu_clock_reset`), CR00, C26 CPU→sys.

SYS-12 requires every fault producer, including CPU wrapper, to hold fault_valid/reason/address until coordinated common reset. CR00 now supplies only clk and cpu_local_rst_n to the CPU block. There is no common rst_n input to that wrapper in the exact connection contract. The wrapper/core reset distinction is therefore incomplete.

Trigger: a core trap is captured; sys asserts local CPU reset. If the wrapper's sticky fault register uses the only supplied local reset, it clears before common reset and violates its producer protocol. If it ignores local reset, it still cannot identify a later common reset to clear the sticky event for a fresh boot, since fatal local reset is already low throughout that interval. Sys's own retained FATAL helps observability but does not repair the contradictory CPU producer interface.

Minimal correction: add common `rst_n` alongside `cpu_local_rst_n` in `cpu_clock_reset`/CR00. State that CPU-wrapper fault metadata is clocked and reset by common rst_n, while the PicoRV32 core uses cpu_local_rst_n. Moving sticky trap capture into a separately common-reset block is another valid choice but would require updating C26/prose. Preserve existing CPU-only fatal reset and retained bridge/fabric state. Owner: architect/CPU/system partition.
