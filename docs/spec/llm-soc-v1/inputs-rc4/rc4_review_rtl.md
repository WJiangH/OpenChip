## Blocking items

### R4-01 — the change order's flush gloss contradicts NPU-09(b) and reopens the F-01 race

`CHANGE_ORDER_rc4.md:9`: "RTL: **npu_ctl** adds `o_dot_lifecycle_flush` (**= not command_live**; set on dma_terminal sample edge and reset, cleared on C25 handshake edge)".

`command_live` in npu_ctl naturally begins at the C12 accept edge — that is the edge NPU-04 (`npu.md:37`) names H and on which the LAST_CYCLES counter starts ("H is the rising edge on which the npu_csr→npu_ctl dispatch handshake (C12) of the command completes"). Nothing in rc4 forces C25 = C12; NPU-09(a) constrains only "C25 … no later than … C13", and a registered forward inside npu_ctl gives C25 = C12+1. With `flush = ~command_live` the level therefore falls at C12, one or more cycles **before** npu_local is re-armed at C25. In that window npu_local may still be offering the previous command's `dot_operands` beat, npu_dot has flush=0, accepts it and accumulates it; if it carried `group_last`, a result with the old row/group_index is formed and npu_dma — armed at C13 — writes it at an address formed from the **new** `y_base`/`gcount`. That is exactly the F-01 corruption path (`inputs-rc4/integrator-review-01.md:22`).

Must change: delete the gloss. Proposed replacement: "RTL: **npu_ctl** adds `o_dot_lifecycle_flush`: reset value 1, set on the dma_terminal sample edge T, cleared **only** on the C25 handshake edge (never on the C12 accept edge)".

### R4-02 — NPU-09(b) states level obligations as edge actions; contract.json states the level. They differ by one cycle and no implementation satisfies both

`npu.md:56` NPU-09(b): "On every rising edge at which flush=1 npu_dot shall clear its result register and accumulator, hold `group_result.valid`=0, present `dot_operands.ready`=1 and discard the operand beat, if any, accepted at that edge".
`contract.json:379` (`group_result.semantics`): "producer never asserts valid while dot_lifecycle.flush=1".

flush is a registered level (`npu.md:56`, `contract.json:453`) that npu_ctl raises at the terminal sample edge T, so it is 1 during the cycle (T, T+1]. npu_dot cannot anticipate that at edge T: any registered `group_result.valid` it holds stays 1 for that whole cycle, and its `dot_operands.ready` likewise stays at its pre-flush value. The edge-worded rule is therefore satisfied one cycle later than the contract's level rule; `valid=0` and `ready=1` are only achievable in the first flush cycle if npu_dot masks both **combinationally** with flush (legal: flush is registered, so §4's "no combinational VALID dependence on READY" is untouched). Two authors reading the two documents produce different waveforms on the one protocol rc4 adds — the F-04 defect class rc4 was written to eliminate.

Must change (npu.md:56, second sentence of (b)). Proposed replacement: "While flush=1 npu_dot shall present `group_result.valid`=0 and `dot_operands.ready`=1 as combinational functions of flush (flush is registered; this creates no VALID-on-READY dependence), and on every rising edge at which flush=1 it shall clear its result register and accumulator and discard the operand beat, if any, accepted at that edge; no result formed from operands accepted while flush=1 is ever offered."

### R4-03 — SYS-13 admits a second normative document that contradicts it, and drops SYS-12's local-reset exception

`system.md:95` SYS-13: "DV may read `hw/ip/picorv32/README.md` at the pinned commit (dependencies.md) sections "PicoRV32 Native Memory Interface" and "Custom Instructions for IRQ Handling" as the normative description of the integrated core's external behaviour".

Inside that admitted section, `hw/ip/picorv32/README.md:403` and `:418` state: "There is no need for an external wait cycle. The memory read can be implemented asynchronously with `mem_ready` going high in the same cycle as `mem_valid`, or `mem_ready` being tied to constant 1." SYS-13 forbids both ("never in the cycle in which mem_valid first rises", "never while mem_valid=0"). No precedence rule is given.
Second contradiction: `README.md:392` "The valid signal stays high until the peer asserts `mem_ready`" and SYS-13's "holds mem_valid … stable until the rising edge on which mem_ready=1 is sampled" have no exception, while `system.md:93` SYS-12 requires the bridge to work "even if CPU drops mem_valid under local reset" — which is what happens on every SYS-07 failing request (`cpu_local_rst_n = rst_n & boot_delay_done & !FATAL`). A native-port monitor derived from SYS-13, as the change order mandates ("DV: unit-level cpu_bridge native driver/monitor derives from SYS-13 + README sections", `CHANGE_ORDER_rc4.md:11`), fails the DUT in every fatal test.

Must change (append to SYS-13). Proposed replacement: "Where the referenced README sections and SYS-13 differ, SYS-13 governs: the README's permission for `mem_ready` in the same cycle as `mem_valid` or tied to 1 does not apply to this bridge. The core's payload-stability obligation is suspended while `cpu_local_rst_n` is low; the bridge shall hold its AXI state and issue no `mem_ready` for the failed request (SYS-07, SYS-12)."

## Checked, no finding

**(1) C34 closes F-01 — explicit cycle walk** (`npu.md:56` NPU-09(a)(b)(d), `contract.json:453`; convention taken from the spec's own "in the cycle ending at that edge flush is still 1", i.e. a level's value *at* an edge is its value during the cycle ending at that edge). Error case, with a completed group stuck in npu_dot:

| edge | npu_dma | npu_dot | flush (level in the cycle **starting** at this edge) |
|---|---|---|---|
| n (first non-OKAY R/B) | `err_q`←1; `group_result.ready`=0 from n onward (NPU-09(d)) | holds result, valid=1 (old row/gidx) | 0 |
| Td (AXI drain complete) | asserts `error`/`error_code`=5 or 6 as registered levels (NPU-09(c)) | unchanged | 0 |
| T = Td+1 (earliest) | levels held | unchanged | npu_ctl samples error=1 → T is the terminal edge; flush←1 |
| T+1 (first edge with flush=1) | — | clears result register + accumulator; `valid`=0; `ready`=1 | 1 |
| C25 ≥ T+1 | — | any stale beat npu_local still offers is accepted **and discarded** at this edge (flush is 1 in the cycle ending here), or retracted by npu_local's re-arm | 0 from C25 |
| C13 ≥ C25 | re-armed: write buffer, held terminal level, undelivered word discarded; `ready` may rise | result register already cleared for ≥1 edge | 0 |
| C13+1 … | first AR permitted | first legal operand no earlier than C25+2, and only after DMA data | 0 |

The degenerate spacing C25 = T+1 = C13 is still safe: flush is 1 in the cycle ending at that edge, so the beat accepted there is discarded and the result register is cleared at the same edge, and NPU-09(d)'s "hold `group_result.ready`=0 until its next dispatch handshake" keeps npu_dma from sinking anything before it. The success path is covered too, because flush also rises on `done` ("samples dma_terminal done or error asserted"), which is what makes the NPU-08 "terminal reuse" case provable. Reset: "drive flush=1 from reset release" fixes the reset value at 1, and npu_dot's own reset clears the same state, so the idle interval is clean. NPU-09(e)'s stop-without-error case never produces T, so flush stays 0 and npu_dot keeps its residue — consistent, because that path "stays BUSY=1 until coordinated reset". The mechanism is sound; R4-01/R4-02 are about the two sentences that describe it, not about the mechanism.

**NPU-06 rewrite is consistent with the flush** — rc3's "no offered/accepted transaction **or unconsumed result** remains" is replaced by "after every offered AR/AW has completed its final R/B handshake … a result still held in npu_dot or operands still held in npu_local are not awaited, because the NPU-09 flush and dispatch re-arm discard them" (`npu.md:41`). With NPU-09(d) holding `group_result.ready`=0 after the error, the rc3 wording was unsatisfiable; the rc4 pair removes the deadlock without weakening the drain obligation.

**(2) `dma_terminal` level semantics are complete for both cases.** `npu.md:56` NPU-09(c): who clears — "npu_dma … all three hold until the edge on which its next dispatch handshake (C13) completes or reset"; when sampled — "npu_ctl shall sample dma_terminal only from the cycle after its own C13 handshake edge"; first assertion — "shall take the first edge T at which done|error is sampled 1 as the terminal edge, and shall not re-sample the level for the same command". C13 is a single event shared by both blocks, so the clear edge D and the start of the consumer's sampling window are the same edge; the first sampled value (at D+1) is the post-clear 0. A terminal → CLEAR → SUBMIT sequence with zero idle cycles therefore cannot produce a spurious second terminal, because the clear is tied to the dispatch edge and not to elapsed idle time — this is the residual risk ISSUE-top-01:86 asked simulation to settle, and it is now settled by text. `error_code` is pinned ("5 or 6 while error=1 and 0 otherwise") and NPU-09(a)'s re-arm list repeats "any held dma_terminal level", so producer and consumer statements agree.

**(4) NPU-09(a) ordering is implementable and self-discharging.** "npu_local shall present dispatch.ready=1 whenever not in reset" + "npu_ctl shall complete the npu_local handshake (C25) no later than the edge on which it completes the npu_dma handshake (C13); the same edge is permitted" ⇒ a simultaneous broadcast satisfies the rule unconditionally, since C25 completes on the first edge its VALID is asserted and C13 can only be later or equal. The field list is sufficient: npu_local needs k (keep masks, group ends `min(K,(g+1)G)`), group (boundaries, ceil(K/G)) and n (`command_last` at row=N-1), all present in `dispatch`; the unused fields are explicitly permitted, which is what an author needs to sink them without a lint waiver. `local_bytes.ready`=0 until the local handshake plus "npu_dma may issue its first AR from the cycle after its own dispatch handshake" reproduce rc3's intent without the wire ISSUE-npu_dma-04 showed does not exist.

**(5) response-code rules — overlaps checked pairwise.** DECERR-over-SLVERR (`axi.md:15`: "a request that is unmapped or unauthorized returns DECERR even if its attributes are also unsupported") also disposes of unmapped+foreign-ID and unmapped+bad-size; the burst-footprint question is answered by `system.md:55` SYS-04 "A burst must fit a single authorized region" (fails ⇒ unauthorized ⇒ DECERR), leaving a 4-KiB crossing **inside** one region as a mapped/authorized attribute error ⇒ SLVERR, so the fabric author's own overlap example is decided. Foreign ID echo ("response echoing the presented ID") is width-representable (ID is 2 bits, `axi.md:5`) and does not contradict "All target responses echo accepted ID" (`axi.md:7`). Ownerless VALID → reason 6 on the sampling edge cannot collide with reason 3 for the same event (it needs no timer), and a genuine same-edge collision is resolved by `system.md:93` "simultaneous events select the lowest numeric reason". WO write-0 (`system.md:65`), RESULT_COMMIT repeat (`system.md:77`), BOOT_STAGE>4 (`:73`), DIVISOR<2 (`:88`), DIVISOR-while-BUSY, bad strobes and RO writes all resolve to SLVERR, so no overlap needs a precedence rule; TX_DATA is correctly excluded from the write-1-only family, which keeps a NUL byte writable. Friction:

- Edge-vs-level phrasing ("on every rising edge at which X=1 … hold Y=0") is the single recurring ambiguity in the new lifecycle text; the spec's own disambiguating idiom ("in the cycle ending at that edge") is used once and would remove it everywhere.
