# External IP intake

Before assigning an adapter's behavior, inspect the selected revision's actual top-level ports and configuration. Check which request metadata and error responses survive the boundary. A native port may already align addresses or consume access-size information; an adapter cannot recover unavailable information by following the requested bus spec. Report the mismatch to the architect before implementation.

Distinguish mode-dependent initiators from targets, and software-visible IRQ/exception behavior from a vendor or ISA family name. Bind documentation and integration diagrams to the same release as the source.

Report the exact top and parameter configuration exercised by a probe. A default-config synthesis is not evidence for the eventual system configuration; a repository command that selects no imported sources is not validation. Preserve strict lint failures. If claiming no latches, inspect the final netlist as well as frontend diagnostics; generic cell counts are not mapped area or timing.

Intake evidence does not close integration, independent DV, compliance or security gates. The author supplies source/version/configuration and concrete interface gaps; the architect owns the resulting contract changes.
